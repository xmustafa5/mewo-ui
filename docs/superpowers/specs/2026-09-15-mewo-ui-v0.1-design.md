# mewo — v0.1 design

**Date:** 2026-09-15
**Status:** approved design, pending implementation plan
**Author:** xmustafa5

## 1. What mewo is

mewo is a public, open-source **shadcn registry** of animated React components and page sections. It is not an npm package. Users install items with the shadcn CLI, and the component's source code is copied into their project:

```bash
npx shadcn@latest add @mewo/hero-aurora
```

Namespace: `@mewo`. GitHub: `xmustafa5/mewo-ui`. License: MIT.

**v0.1 scope:** six showcase components and two sections that compose them, a docs site with live demos, an install-verification pipeline, and a first deploy. Animated interactive primitives (dialog, tabs, …) are milestone 2.

**Positioning:** the registry directory already lists 86 animation-focused registries and ~20% of all listed registries are degraded or unavailable. mewo's differentiator for v0.1 is not novelty; it is that every item installs cleanly on the first try, respects reduced-motion, and pulls in only the dependency it actually needs (some items need nothing, some need Motion, some need GSAP).

## 2. Architecture

One Next.js 16 app (this repo) does two jobs:

1. **Docs site** — landing page, one page per item with a live demo, install command, props table and source.
2. **Registry server** — serves one JSON file per item at `/r/<name>.json`, generated at build time by `shadcn build`.

```
you write                          you run          Vercel serves                        user runs
registry/mewo/ui/text-shimmer.tsx → shadcn build → mewo-ui.vercel.app/r/text-shimmer.json → npx shadcn add @mewo/text-shimmer
                                                                                                    ↓
                                                                              their-app/components/ui/text-shimmer.tsx
```

The docs site imports demos straight from `registry/`, so what a visitor plays with is byte-for-byte what `shadcn add` delivers. Demos cannot drift from shipped code.

### Why `registry/mewo/ui/` and not `registry/mewo/`

Verified against shadcn CLI 4.21.0 source. On install, imports are rewritten:

```
@/registry/<x>/ui/name          → @/components/ui/name
@/registry/<x>/components/name  → @/components/name
@/registry/<x>/lib/name         → @/lib/name
@/registry/<x>/hooks/name       → @/hooks/name
@/registry/<x>/name             → @/components/name       (anything else)
```

A `registry:ui` file installs to `components/ui/`. An import of `@/registry/mewo/aurora-background` would be rewritten to `@/components/aurora-background` — a broken import. Placing components under `ui/` makes the rewrite land in the right place. Sections import components as `@/registry/mewo/ui/<name>`.

## 4. Shipped-file rules

Apply to every file under `registry/mewo/`:

1. Starts with `"use client"`.
2. Allowed imports only: `react`, `@/lib/utils`, `motion/react`, `gsap`, `gsap/ScrollTrigger`, `@gsap/react`, `lucide-react`, `@/components/ui/button` (blocks only; resolves to the shadcn core item `button`), and `@/registry/mewo/ui/*` (blocks only). Nothing from `components/site`, `components/demos`, or `lib/registry`.
3. Every component accepts `className` and merges it with `cn(base, className)` on its root element, and forwards remaining props to the root element.
4. Every animated component honours `prefers-reduced-motion`:
   - CSS keyframes: use the `motion-safe:` Tailwind variant so the animation only applies when the user has not asked for reduced motion.
   - Motion: `useReducedMotion()`; when true, render the final state with no transform.
   - GSAP: `gsap.matchMedia()` with `(prefers-reduced-motion: no-preference)` for the animated branch; the other branch `gsap.set`s the final state.
5. Keyframes are declared in the item's `css` field in `registry.json`, never hand-written in `globals.css`. The component references them with a Tailwind arbitrary animation value, e.g. `motion-safe:animate-[shimmer_2s_linear_infinite]`.
6. `ui` items do not import other `ui` items in v0.1. Only blocks compose.
7. Sections are single-file in v0.1.

## 5. Registry catalog

`registry.json`:

```json
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "mewo",
  "homepage": "https://mewo-ui.vercel.app",
  "items": [ ... ]
}
```

`homepage` is the single source of truth for the site URL; `lib/site.ts` reads it. Changing the domain later is a one-field edit.

Item fields used: `name`, `type`, `title`, `description`, `categories`, `dependencies`, `registryDependencies`, `files`, `css`.

- `categories[0]` is the sidebar group. Components use one of `text`, `card`, `scroll`, `background`, `layout`. Sections use `sections`.
- `dependencies` lists only npm packages the file imports.
- Sections reference components as `@mewo/<name>` in `registryDependencies` and shadcn core items by bare name (`button`). The `@mewo` form resolves through the registry directory once listed, through a `registries` entry in the user's `components.json` before that, and through a localhost mapping in `verify-install.sh`.

### Components (`registry:ui`, file at `registry/mewo/ui/<name>.tsx`, file type `registry:ui`)

| name | description | props (all optional unless noted) | deps | `css` |
|---|---|---|---|---|
| `text-shimmer` | Light sweep across text | `children: string` (required), `duration=2` (s), `className` | — | `@keyframes shimmer` |
| `marquee` | Infinite horizontal scroll, seamless loop | `children` (required), `direction="left"\|"right"`, `speed=30` (s per loop), `pauseOnHover=true`, `className` | — | `@keyframes marquee` |
| `split-text` | Characters/words stagger in when scrolled into view | `children: string` (required), `by="chars"\|"words"`, `stagger=0.03`, `delay=0`, `once=true`, `as="span"\|"h1"\|"h2"\|"h3"\|"p"`, `className` | `gsap`, `@gsap/react` | — |
| `spotlight-card` | Radial glow follows the pointer across a card | `children` (required), `spotlightColor="rgba(255,255,255,0.15)"`, `className` | `motion` | — |
| `scroll-reveal` | Fades/slides children in on viewport entry | `children` (required), `direction="up"\|"down"\|"left"\|"right"\|"none"`, `distance=24` (px), `delay=0`, `duration=0.6`, `once=true`, `className` | `motion` | — |
| `aurora-background` | Slow animated gradient backdrop with content entrance | `children` (required), `showRadialMask=true`, `className` | `motion` | `@keyframes aurora` |

Implementation notes:
- `marquee` renders its children twice inside a translating track so the loop is seamless; the keyframe moves the track from `0` to `-50%`.
- `split-text` splits the string itself (no GSAP SplitText plugin). Each unit is a `span` with `display:inline-block`; whitespace is preserved. Trigger: `ScrollTrigger` with `start: "top 85%"`. Uses `useGSAP` for lifecycle cleanup.
- `spotlight-card` uses `useMotionValue` for pointer x/y and `useMotionTemplate` to build the radial-gradient background of an overlay layer.
- `scroll-reveal` uses `motion.div` with `initial` / `whileInView` and `viewport={{ once, margin: "-10%" }}`.
- `aurora-background` layers two blurred gradient elements animated by `@keyframes aurora` (background-position drift) and fades its children in with Motion.

### Sections (`registry:block`, file at `registry/mewo/blocks/<name>.tsx`, file type `registry:component`)

| name | composed from | registryDependencies | extra deps |
|---|---|---|---|
| `hero-aurora` | `AuroraBackground` → eyebrow text, `SplitText as="h1"` headline, paragraph, primary + secondary `Button` | `button`, `@mewo/aurora-background`, `@mewo/split-text` | — |
| `features-spotlight` | `TextShimmer` eyebrow, heading, `ScrollReveal` wrapping a 3-column grid of `SpotlightCard`s (icon, title, description), `Marquee` of logo placeholders underneath | `@mewo/text-shimmer`, `@mewo/scroll-reveal`, `@mewo/spotlight-card`, `@mewo/marquee` | `lucide-react` |

Both sections take optional props with sensible defaults so `<HeroAurora />` and `<FeaturesSpotlight />` render complete out of the box:
- `hero-aurora`: `eyebrow`, `title`, `description`, `primaryCta: { label, href }`, `secondaryCta: { label, href }`, `className`.
- `features-spotlight`: `eyebrow`, `title`, `features: { icon?, title, description }[]`, `logos: ReactNode[]`, `className`.

Between them the two sections use all six components — they are the proof that the components compose.

## 6. Docs site

Everything is generated from `registry.json` via `lib/registry.ts`. Adding an item to the catalog adds its sidebar entry, its page and its preview route; there is no second list to maintain.

`lib/registry.ts` exposes: `getItems()`, `getItem(name)` (undefined if missing), `getGroups()` (ordered: `sections` first, then component groups in the order `text`, `card`, `scroll`, `background`, `layout`), `isBlock(item)`.

### Pages

- `/` — landing. Renders `HeroAurora` and `FeaturesSpotlight` with mewo's own copy, then a grid of cards linking to every item. The site dogfoods its own registry.
- `/docs` — what mewo is; install instructions: the `registries` snippet for `components.json`, the directory note, and the raw-URL fallback.
- `/docs/[name]` — `generateStaticParams` from the catalog; unknown name → `notFound()`. Sections in order:
  1. Title, description, dependency badges (`motion` / `gsap` / none).
  2. Preview. Components: `ComponentPreview` with Preview / Code tabs, demo rendered inline in a bordered box. Sections: `BlockPreview` — an `<iframe src="/preview/<name>">` with desktop (100%) / tablet (768px) / mobile (390px) width toggles, plus the same Code tab.
  3. `InstallCommand`: `npx shadcn@latest add @mewo/<name>` with a copy button; a collapsed "not using the directory?" line shows `npx shadcn@latest add <SITE_URL>/r/<name>.json`.
  4. `PropsTable` from the demo file's exported `props`.
  5. Source: the shipped file, read from disk in a server component and highlighted with `shiki` (dual theme via CSS variables so it follows dark mode). For display only, `@/registry/mewo/ui/` is rewritten to `@/components/ui/` so the reader sees what will land in their project.
- `/preview/[name]` — renders the block's demo full-bleed with no header or sidebar. Non-block name → `notFound()`.

### Demo files

`components/demos/<name>-demo.tsx` exports:
- `default` — a React component rendering the item with representative props.
- `props: PropDoc[]` where `PropDoc = { name: string; type: string; default?: string; description: string }`.

`components/demos/index.ts` maps item name → module. `lib/registry.ts` does not import demos (keeps the catalog free of client code); the docs page joins the two.

### Site components (`components/site/`)

`Header`, `Sidebar`, `ThemeToggle`, `ComponentPreview` (client: tabs), `BlockPreview` (client: iframe + width toggle), `CodeBlock` (server: shiki), `InstallCommand` (client: copy), `PropsTable`, `DependencyBadges`. Dark mode via `next-themes`. No MDX framework in v0.1.

### shadcn config for the docs site (`components.json`)

Tailwind v4 (`tailwind.config: ""`, `css: app/globals.css`), style `new-york`, base colour `neutral`, `cssVariables: true`, `rsc: true`, `tsx: true`, aliases `@/components`, `@/components/ui`, `@/lib`, `@/lib/utils`, `@/hooks`. The docs site's own shadcn components (`button`, `tabs`, …) live in `components/ui/` and are never shipped.

## 7. Build and generated files

`package.json` scripts:

```json
{
  "dev": "next dev",
  "predev": "npm run registry:build",
  "build": "npm run registry:build && next build",
  "registry:build": "shadcn build && tsx scripts/registry-css.ts",
  "lint": "eslint",
  "typecheck": "tsc --noEmit",
  "test": "vitest run",
  "verify:install": "bash scripts/verify-install.sh"
}
```

- `shadcn build` reads `registry.json` and writes `public/r/<name>.json` (source embedded). Invalid catalog → non-zero exit → build fails.
- `scripts/registry-css.ts` reads `registry.json`, collects every item's `css` object, serialises it to CSS (object value → nested block, string value → declaration; property names are already kebab-case in the catalog), and writes `app/registry.css` with a `/* GENERATED from registry.json — do not edit */` header. `globals.css` has `@import "./registry.css";`. Unknown value shape → throw naming the item, failing the build loudly.
- `.gitignore` adds `public/r/` and `app/registry.css`. Both regenerate on every `dev` and `build`.

## 8. Install verification (`scripts/verify-install.sh`)

The test that matches what the registry directory's health checker measures ("installability"), run before deploy instead of after:

1. `npm run build`, then `next start -p 3999` in the background; `trap` kills it on exit.
2. In the session scratch directory: `create-next-app` (TypeScript, Tailwind, App Router, `@/*` alias, no `src/`), then `shadcn init -d`.
3. Write `"registries": { "@mewo": "http://localhost:3999/r/{name}.json" }` into the scratch `components.json`.
4. For every item name in `registry.json`: `npx shadcn@latest add @mewo/<name> --yes --overwrite`. Sections exercise dependency resolution against the local server.
5. `npx tsc --noEmit` in the scratch app.
6. Any step failing exits non-zero.

Runs in GitHub Actions (`.github/workflows/ci.yml`, Node 22) on every push and pull request, after `lint`, `typecheck` and `test`.

## 9. Testing

Vitest + `@testing-library/react` + jsdom. `vitest.config.ts` sets the `@` alias and a setup file that stubs `matchMedia`, `IntersectionObserver` and `ResizeObserver` (needed by Motion and ScrollTrigger under jsdom). Tests live outside `registry/` so the shipped-only rule holds:

- `tests/ui/<name>.test.tsx` — one per component: renders; forwards `className` to the root; honours its documented props (e.g. `split-text` with `by="words"` renders one span per word; `marquee` renders children twice; `text-shimmer` renders the string).
- `tests/blocks/<name>.test.tsx` — renders with defaults; renders supplied props (title, CTA labels, feature count).
- `tests/registry.test.ts` — catalog invariants: every `files[].path` exists; names are kebab-case and unique; every item has a demo in `components/demos/index.ts`; every `@/registry/mewo/ui/<x>` import in a block appears as `@mewo/<x>` in that block's `registryDependencies`; every `css` key starts with `@keyframes` or `@utility`; every shipped file starts with `"use client"`; `ui` files do not import other `ui` files.
- `tests/scripts/registry-css.test.ts` — serialiser: nested keyframes produce the expected CSS; a non-object, non-string value throws with the item name.

Development follows TDD: the test for a component is written before the component.

## 10. Error handling

- Unknown `[name]` on docs or preview routes → `notFound()`.
- `registry-css.ts` → throws with item name on malformed `css`; build fails.
- Invalid `registry.json` → `shadcn build` fails; build fails.
- `verify-install.sh` → fail fast, always cleans up the server.
- Shipped components are defensive about SSR: `split-text` and `spotlight-card` only touch `window`/pointer inside effects and event handlers.

## 11. Deployment and listing

- Vercel project linked to `xmustafa5/mewo-ui`, default Next.js build. First URL: `https://mewo-ui.vercel.app`. A custom domain later means editing `homepage` in `registry.json` and redeploying.
- After the first green deploy: open a PR to `shadcn-ui/ui` adding to `apps/v4/registry/directory.json`:

  ```json
  { "name": "@mewo", "homepage": "https://mewo-ui.vercel.app", "url": "https://mewo-ui.vercel.app/r/{name}.json", "description": "Animated React components and sections powered by Motion and GSAP." }
  ```

  and run `pnpm validate:registries` in that repo. The README carries this as a checklist. Until merged, users add the `registries` snippet from `/docs`.

## 12. Repo hygiene

- `README.md`: what mewo is, install (directory + snippet), item list with one-line descriptions, "adding a component" (write file → catalog entry → demo → test → `npm run verify:install`), directory-listing checklist, license.
- `LICENSE`: MIT, copyright 2026 xmustafa5.
- Commit convention from `CLAUDE.md`: every message starts with `mewo : `; no AI attribution lines.
- Next.js 16 has breaking changes versus older versions (see `AGENTS.md`). Before writing app code, read the relevant guides under `node_modules/next/dist/docs/01-app/` — at minimum dynamic routes, `generateStaticParams`, and metadata. Route `params` are async and must be awaited.

## 13. Out of scope for v0.1 (deliberate)

- Animated accessible primitives (dialog, dropdown, tabs, accordion, toast) — milestone 2, built on Radix or Base UI.
- Arabic / RTL documentation. Components must not break under `dir="rtl"`, but no RTL-specific work.
- MDX docs framework, site search, per-item versioning, an npm package, a paid tier, "Open in v0", custom domain purchase.
- Multi-file sections.
