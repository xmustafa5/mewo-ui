# mewo v0.2 — animated drop-in primitives

**Date:** 2026-09-17
**Status:** approved design, pending implementation plan
**Author:** xmustafa5
**Follows:** `docs/superpowers/specs/2026-09-15-mewo-ui-v0.1-design.md`

## 1. What this is

Two **drop-in replacements** for components shadcn already ships. A user with an existing
shadcn app runs one command and their tabs or collapsible gain real motion, with no code change:

```bash
npx shadcn@latest add @mewo/tabs
```

The file lands at `components/ui/tabs.tsx`, overwriting shadcn's. Every import, every prop and
every export keeps working. That is the whole promise, and it is also the whole constraint.

## 2. Why these two, and why not the others

The gap was **measured**, not read. Each candidate was installed into a clean Next.js app,
rendered in Chromium, triggered, and sampled every animation frame. Reading the source proved
unreliable three separate times during this design — a component can look animated and jump, or
look bare and animate — so only frame-sampled results are recorded as findings here.

| Component | Measurement | Verdict |
|---|---|---|
| **tabs** | Active highlight moves x=43 → x=172 in 3ms; **2** distinct positions across 500ms. `TabsList` contains only three `tabs-trigger` children — no indicator element exists. Only the background colour cross-fades (11 distinct colours). | **Gap: the highlight teleports** |
| **collapsible** | Panel height appears at 72px on the first frame after `aria-expanded=true`; **1** distinct height across 500ms. Source is a bare pass-through: `CollapsibleContent` renders `<CollapsiblePrimitive.Panel data-slot="collapsible-content" {...props} />` with no className at all. | **Gap: no animation whatsoever** |
| accordion | **13** distinct heights over ~200ms on a decelerating curve (0 → 13.8 → 26.5 → 38.6 → 49.8 → 60.2 → 69.8 → 78.4 → 86 → 92.4 → 97.4). Uses `h-(--accordion-panel-height)` with `data-starting-style:h-0` / `data-ending-style:h-0`. | No gap — **excluded** |
| drawer | Not frame-measured. Source shows `Drawer.Handle`, `swipe`, durations 200/300/450ms. | No apparent gap — **excluded** |
| carousel | Not frame-measured. Not a Base UI component: wraps `embla-carousel-react`, whose own description is "fluid motion and great swipe precision". | No apparent gap — **excluded** |
| popover, tooltip, select, dropdown-menu, dialog, menubar, context-menu, switch | **Unmeasured.** A batch measurement rig produced self-contradicting results (called `dialog` static despite its `animate-in`/`zoom-in-95`/`fade-in-0` classes; flipped `dropdown-menu` between runs) because its portal selectors matched wrapper elements rather than animated ones. Its output is discarded. | **Unknown — not cleared** |

The most useful finding is structural: **accordion and collapsible are siblings, and shadcn
animated one and forgot the other.** Accordion receives a height variable, starting and ending
styles, `overflow-hidden` and keyframes. Collapsible receives nothing. That is an oversight, not
a design decision, and it is exactly what a registry should fill.

The last row matters as much as the others. Those eight components are **not** known to be
well-animated; they are unmeasured. A future milestone that wants them must measure each in
isolation first, the way tabs, collapsible and accordion were measured here.

## 3. Scope

**In:** `tabs`, `collapsible`.

**Out, deliberately:** accordion (measured as already animated — shipping it would put a false
claim in the README), drawer, carousel, dialog, dropdown-menu, toast (no apparent gap); popover,
tooltip, select, menubar, context-menu, switch (unmeasured, see §2); any component shadcn does
not ship (a drop-in has nothing to drop into); a CI job that diffs mewo's API against shadcn's
live registry (§8 — belongs in v0.3).

## 4. The drop-in contract

This is the requirement everything else serves. Installing must not break a working app.

**tabs.tsx must export exactly:**
`Tabs`, `TabsList`, `TabsTrigger`, `TabsContent`, `tabsListVariants`

**collapsible.tsx must export exactly:**
`Collapsible`, `CollapsibleTrigger`, `CollapsibleContent`

Prop types must remain the Base UI types shadcn uses:

| Export | Props |
|---|---|
| `Tabs` | `TabsPrimitive.Root.Props`, `orientation` defaulting to `"horizontal"` |
| `TabsList` | `TabsPrimitive.List.Props & VariantProps<typeof tabsListVariants>`, `variant` defaulting to `"default"` |
| `TabsTrigger` | `TabsPrimitive.Tab.Props` |
| `TabsContent` | `TabsPrimitive.Panel.Props` |
| `Collapsible` | `CollapsiblePrimitive.Root.Props` |
| `CollapsibleTrigger` | `CollapsiblePrimitive.Trigger.Props` |
| `CollapsibleContent` | `CollapsiblePrimitive.Panel.Props` |

`tabsListVariants` keeps both of shadcn's variants: `default` and `line`.

Adding optional props is allowed. Removing, renaming or changing the type of anything above is
a breaking change for every installed user and is forbidden without a major version.

## 5. Tabs — the design

shadcn renders no indicator. mewo adds one, animated with Motion's shared-layout engine.

- Each `TabsTrigger` uses Base UI's `render` prop to read `state.active` (verified present on
  `Tabs.Tab`), and renders a `motion.div` with `layoutId="mewo-tab-indicator"` only when active.
- Motion animates the indicator between triggers as the shared layout element moves. Because
  shared-layout animation runs only on subsequent renders, the first paint is static and
  correct — there is no hydration flash.
- Transition: spring, `{ type: "spring", stiffness: 380, damping: 32 }`. The implementer may
  tune these two numbers if the result feels wrong; no other transition property changes.
- `useReducedMotion()` true → `{ duration: 0 }`, so the indicator snaps instead of sliding.
- The indicator is decorative: `aria-hidden`, `pointer-events-none`, positioned `absolute
  inset-0` behind the label, `z-0` with the label at `z-10`.
- **Both `tabsListVariants` variants must be handled**, because they highlight differently.
  `default` fills the active trigger with `data-active:bg-background`; `line` draws a 2px
  underline via an `after:` pseudo-element whose opacity toggles. The sliding indicator replaces
  the moving part of each: a rounded pill for `default`, a bar for `line`. The variant is
  readable from `TabsList`'s `data-variant` attribute, which shadcn already sets.
- `TabsList` gets `relative` so the indicator positions against it.
- Base UI's `Tabs.Indicator` part is **not** used. Its CSS variables are an alternative
  implementation of the same feature; using both would animate the indicator twice.

`orientation="vertical"` must work: the indicator is `inset-0` on the active trigger, so it
follows whatever box Base UI lays out, in either direction.

## 6. Collapsible — the design

shadcn's `collapsible.tsx` is a bare pass-through. Every part renders the Base UI primitive with
a `data-slot` and nothing else — no className, no height handling, no animation. Measurement
confirms it: the panel appears at full height on the first frame.

mewo's version brings it to the standard shadcn already applies to accordion, and adds motion
on top:

1. **Animated height.** Base UI's Collapsible exposes `--collapsible-panel-height` on the panel,
   the direct analogue of the `--accordion-panel-height` that shadcn's accordion already uses.
   `CollapsibleContent` wraps its children in an element sized by that variable, with
   `data-starting-style:h-0` and `data-ending-style:h-0` for enter and exit, and `overflow-hidden`
   to clip during the transition.
2. **Eased height — CSS transition, not a Motion spring.** *(Amended after implementation. This
   bullet originally specified a `motion.div` driving the height with
   `{ type: "spring", stiffness: 400, damping: 40 }`. That is not what shipped, and the code is
   right.)* Base UI owns the height: it measures the panel, publishes
   `--collapsible-panel-height`, and branches at runtime on the panel's **computed
   `transition-duration`** to decide when the open/close transition has finished. A Motion spring
   would duplicate that measurement and animate a property Base UI's own state machine is already
   reading, so the two would fight. The panel therefore transitions its own height in CSS —
   `motion-safe:transition-[height] motion-safe:duration-200 motion-safe:ease-out` — which is also
   exactly how shadcn's already-animated accordion does it. Motion stays, driving only the opacity
   of the content wrapper (bullet 3). Measured result: **12 distinct heights on a decelerating
   ramp**, against 1 for shadcn's unanimated original and 13 for its accordion — the outcome this
   bullet was written to obtain.
3. **Content fade.** Children fade from `opacity: 0` as the panel opens, so text does not appear
   fully-formed inside a box that is still growing.
4. **Reduced motion.** `useReducedMotion()` true → `{ duration: 0 }` and no fade; the panel
   simply appears at full height, which is exactly shadcn's current behaviour.

The open state comes from Base UI's `render` prop on `Collapsible.Panel`, which exposes
`open: boolean` (verified present on the installed types). No internal Base UI context hook is
used — those are not part of the public surface and could change without notice.

## 7. Constraint change

v0.1's `tests/registry.test.ts` enforces a shipped-file import allowlist that does **not**
include Base UI. v0.2 widens it deliberately:

**Added to the allowlist:** `@base-ui/react/tabs`, `@base-ui/react/collapsible`,
`class-variance-authority`.

**New invariant to accompany it:** an item may import `@base-ui/react/*` only if its `name`
matches a component shadcn ships — that is, only drop-in replacements may reach for Base UI.
This keeps v0.1's showcase components dependency-light and stops the allowlist widening again
by accident.

`dependencies` in `registry.json` must list `motion`, `@base-ui/react` and (for tabs)
`class-variance-authority`, matching what each file imports — the existing invariant already
checks this and must keep passing. Note `cn` is imported as `@/lib/utils`, mewo's existing
convention, not as the bare `cn` package shadcn's own files use; both resolve in any project
`shadcn init` has set up, and `@/lib/utils` keeps the item free of an extra npm dependency.

## 8. The risk, on the record

**A drop-in inherits upstream's API.** If shadcn renames a prop or restructures `tabsListVariants`,
mewo diverges silently and users get subtle breakage on an app that previously worked.

v0.2's mitigation is narrow and honest: a test pins the exact export names, so an accidental
rename inside mewo fails the suite. It does **not** detect shadcn changing their side. The real
fix is a scheduled CI job that fetches `https://ui.shadcn.com/r/styles/base-nova/{tabs,collapsible}.json`
and diffs the export list and prop types against mewo's. That belongs in v0.3; inflating v0.2
with it would delay two components behind a piece of infrastructure.

Until then the README must state plainly which shadcn version each drop-in was verified against.

## 9. Testing

Follows v0.1's structure: tests live outside `registry/`, the catalog invariants in
`tests/registry.test.ts` must stay green, and `npm run verify:install` must still install every
item into a fresh app and typecheck it.

- `tests/ui/tabs.test.tsx` — renders; all five exports exist; `tabsListVariants` produces both
  `default` and `line`; the active trigger renders exactly one indicator and inactive triggers
  render none; the indicator carries `aria-hidden`; `className` merges onto each part; vertical
  orientation renders; switching tabs moves the indicator to the newly active trigger.
- `tests/ui/collapsible.test.tsx` — renders; all three exports exist; the trigger toggles
  `aria-expanded`; content is present and reachable when open; `className` merges; the panel
  carries `overflow-hidden` so the height animation clips.
- `tests/registry.test.ts` — extended with the §7 invariant (only drop-in-named items may import
  Base UI), plus a test asserting the exact export-name lists from §4 so a rename cannot ship
  silently.

**Tests assert structure and accessibility, never animated pixel values.** jsdom has no layout
engine, so a test cannot tell a smooth transition from a jump — which is precisely how v0.1
shipped a zero-width space that passed every test. Animation quality is verified the way the
gaps in §2 were found: by rendering in a real browser and sampling frames. That verification is
a manual step recorded in the implementation plan, not an automated test.

## 10. Docs

No new site machinery. Both items are `registry:ui` and flow through the existing generated
sidebar, item page, props table and source view. Each needs a demo at
`components/demos/<name>-demo.tsx` registered in `components/demos/index.ts`.

Two additions to the existing docs:

- A new catalog category `primitives`, so drop-ins group separately from showcase components
  in the sidebar. This means editing **two** constants in `lib/registry.ts`, not one:
  `GROUP_ORDER` (insert `"primitives"` after `"sections"`) and `GROUP_LABELS` (add
  `primitives: "Primitives"`). `GROUP_LABELS` is typed `Record<Group, string>` where `Group`
  derives from `GROUP_ORDER`, so changing only one of them fails `npm run typecheck`.
- Each drop-in's docs page must state that installing **overwrites** the shadcn file of the
  same name, and name the shadcn version it was verified against (4.21.0).
- Each drop-in's page should show what it improves. For tabs that is the sliding indicator; for
  collapsible it is that shadcn's version has no animation at all.

## 11. Out of scope for v0.2

Accordion (measured as already animated). Dialog, dropdown-menu, toast, drawer, carousel (no
apparent gap). Popover, tooltip, select, menubar, context-menu, switch (unmeasured — a later
milestone must measure each in isolation before claiming a gap). Gesture-driven components. The
upstream API-drift CI job (v0.3). Any change to v0.1's six showcase components or two sections.
RTL-specific work. A major-version bump — v0.2 is additive.
